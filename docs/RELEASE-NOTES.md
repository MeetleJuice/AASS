One All Tests view runs eight versioned isolated benchmarks with real Docker
acceptance checks, incremental metadata events, honest completion counts,
cancellation, native Windows completion notification, review and sanitized ZIP
export. Optional live worker/cloud checks require explicit run consent and share
the unchanged hard budget. Fixtures never establish live model capability.

Execution repairs use action-specific required schemas, field-level corrective
feedback, preserved test failures and runnable-snapshot verification checkpoints.
Repeated ineffective snapshots are intercepted, independent benchmark checks are
protected, and test/review gates and installation/update security remain intact.
No extra models, dependencies, runtime agents or automatic diagnostic uploads.

Physical Windows 10 and live RTX 3050/Ollama/provider acceptance remain destination
checks. Passing fixture benchmarks or Windows Server CI cannot establish those.

# AASS 1.3.2 — recover repeated worker rewrites

A user trajectory showed six writes to calculator.py interleaved with four
invalid model responses, no test actions and no strategy pivot. Successful writes
had masked the fixation detector. Three writes to the same path without a test
or a new artifact now force a bounded strategy change even across model errors.
Worker context includes bounded file/definition summaries and explicit guidance
to complete the other requested artifacts. Protocol errors distinguish invalid
JSON, invalid action schema and truncated output without logging raw responses.
Qwen3 schema-action calls disable optional thinking and request at most 2048
output tokens, with the matching full reservation charged before every request.
The 64,000-token and 20-iteration ceilings and strict test/judge gates remain.
The desktop progress stream now reports each step's action and reserved budget.

A regression replays mixed rewrite/protocol failures, pivots, writes calculator,
unittest and README files, executes eight actual Docker tests including CLI and
decimals/zero, and exercises the review gate using a fixture judge. Model decisions
are fixtures; this does not prove a live Qwen/Gemini task on the user's machine.
The release remains subject to all native Windows and security/publication gates.

# AASS 1.3.0 - permanent desktop app and verified updates

Extract a full ZIP and double-click Install-AASS.bat. AASS checks the latest
verified release, installs in a permanent per-user folder and creates a custom
Windows desktop icon after local setup passes. Code ZIPs fetch the verified
release first. Existing model tools and private file selections are preserved.

The app now has an Update button. It downloads complete published releases and
checks archive hashes, source manifest and matching scan/audit evidence. After
closing the GUI it backs up source and runtime, installs needed changes, verifies
runtime/GUI/browser operation and restarts. Failure rolls back; interrupted copy
recovery loads the complete old engine before importing application modules.
Source-only changes reuse locked dependencies. No paid model check is automatic.

Windows CI exercises clean managed bootstrap, real COM desktop shortcut and ICO
loading, actual GUI/runtime/browser installation, update/rollback regressions,
and Microsoft Defender scans of the ZIP and installed payload before publication.

# AASS 1.2.1 — align Gemini discovery and review

Gemini's dropdown lists models advertising native generateContent. The judge now
uses that same native API, instead of assuming each listed model is available
through Google's OpenAI compatibility endpoint. Existing official Google endpoint
settings migrate in memory; keys remain in the same private file. No additional
SDK or automatic paid retry is introduced.

Connection progress and errors identify the selected provider, model and API
route. Recognized Google key restrictions, disabled API/project billing and
invalid-key reason codes provide specific recovery guidance without displaying
provider messages or key values. A successful local worker check is retained
while retrying the cloud. Local installation is already complete when only the
cloud check fails.

Native replies require a complete structured verdict. Blocked, incomplete,
thought-only and malformed responses fail closed. Model listing does not prove
account entitlement or quota; actual connection testing still requires the
user's own key on their PC. Windows/runtime/Defender publication gates remain.

# AASS 1.2.0 — guided setup and model discovery

Double-click Install-AASS.bat to open one graphical setup window. It reuses local
tools, displays progress and offers cancellation. Choose an existing private
credential file, select a provider and pick an actual returned text model from its
catalog. App-local .env/.env.txt and BOM-marked Notepad UTF-16 files are supported.
Only the selected path and provider/model preferences are saved.

Local installation makes no paid cloud requests. Explicit connection tests report
authentication, access, missing-model and quota errors in the same window. A
successful worker check is retained while retrying the cloud judge. Run a task
using a folder picker and task field; task tests and independent approval remain
mandatory. Advanced CLI and the legacy terminal menu remain available.

Publication requires Linux/Windows verification, actual Windows GUI construction,
hash-locked runtime/browser installation, dependency/source checks and matching
Microsoft Defender scans of the archive and installed payload. Inspect the exact
release's attached scan report and SHA256SUMS; source remains unsigned. Windows
virtualization/restarts and API account billing/access still require the owner.

# AASS 1.1.0 — reviewed installation and distribution

This source release replaces the withdrawn diagnostic patch distribution.
Extract the complete ZIP and double-click Install-AASS.bat. Existing Docker,
Ollama and models are reused. Local installation and cloud account verification
are separate; use the menu to choose your provider and check connections.

Runtime packages/build tools are hash-locked; known filelock advisories were
fixed. Credential access/routing and subprocess environment boundaries were
restricted. Atomic workspace edits, nonregular-file/hardlink checks and browser
WebSocket restrictions address concrete audit findings.

The release is accompanied by its exact Microsoft Defender report, SHA256SUMS,
dependency audit, source security report, SBOM and GitHub build attestation. These
are integrity/scan evidence, not an Authenticode publisher signature or a promise
that all security products accept the source. Do not disable Windows protection
if another warning appears. The original detection name remains unknown.
